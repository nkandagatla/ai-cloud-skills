# Amazon S3

Load `cloud-guardrails`. S3 holds most companies' data; public exposure is the most common cloud breach. Object reads can expose sensitive data: do not download or print object contents unless the user asked for that specific object.

## 1. Bucket baseline (every bucket)

```hcl
resource "aws_s3_bucket" "this" {
  bucket = "acme-orders-prod-use1-111122223333"
  tags   = local.tags
}
resource "aws_s3_bucket_public_access_block" "this" {
  bucket                  = aws_s3_bucket.this.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
resource "aws_s3_bucket_ownership_controls" "this" {
  bucket = aws_s3_bucket.this.id
  rule { object_ownership = "BucketOwnerEnforced" }   # ACLs disabled
}
resource "aws_s3_bucket_server_side_encryption_configuration" "this" {
  bucket = aws_s3_bucket.this.id
  rule {
    apply_server_side_encryption_by_default { sse_algorithm = "aws:kms", kms_master_key_id = var.kms_key_arn }
    bucket_key_enabled = true
  }
}
resource "aws_s3_bucket_versioning" "this" {
  bucket = aws_s3_bucket.this.id
  versioning_configuration { status = "Enabled" }
}
resource "aws_s3_bucket_policy" "tls_only" {
  bucket = aws_s3_bucket.this.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid = "DenyInsecureTransport", Effect = "Deny", Principal = "*", Action = "s3:*",
      Resource = [aws_s3_bucket.this.arn, "${aws_s3_bucket.this.arn}/*"],
      Condition = { Bool = { "aws:SecureTransport" = "false" } }
    }]
  })
}
```

Plus: lifecycle rules (expire noncurrent versions, abort incomplete multipart uploads after 7 days, transition to IA/Glacier per data class), server access logging or CloudTrail data events for sensitive buckets, `lifecycle { prevent_destroy = true }` on critical buckets. Account-level Block Public Access on in every account.

## 2. Access patterns (choose the narrowest)

| Need | Pattern |
| --- | --- |
| Workload in same account | IAM role policy with bucket/prefix ARNs; no bucket policy needed |
| Another account in the org | Bucket policy with specific role ARNs + `aws:PrincipalOrgID`; KMS key policy must allow too |
| Many consumers with different prefixes | **S3 Access Points** (VPC-only access points for internal) with per-access-point policies |
| Only from your VPC | Bucket policy deny unless `aws:SourceVpce` (careful: also blocks console and CI unless exempted) |
| Public website / downloads | **CloudFront + Origin Access Control**; bucket stays private; policy allows `cloudfront.amazonaws.com` with `AWS:SourceArn` = distribution |
| Temporary sharing | Presigned URL, short expiry (minutes), generated by the app's role; never by an admin identity |
| Third-party SaaS | Dedicated role with `sts:ExternalId`, prefix-scoped |

## 3. Read-only discovery

```bash
aws s3api list-buckets --query "Buckets[].Name" --output text
aws s3api get-bucket-location --bucket B
aws s3api get-public-access-block --bucket B
aws s3api get-bucket-policy-status --bucket B                 # IsPublic
aws s3api get-bucket-ownership-controls --bucket B
aws s3api get-bucket-encryption --bucket B
aws s3api get-bucket-versioning --bucket B
aws s3api get-bucket-policy --bucket B --query Policy --output text | jq .
aws s3api get-bucket-lifecycle-configuration --bucket B
aws s3api get-object-lock-configuration --bucket B
aws s3 ls s3://B/prefix/ --summarize --human-readable          # names and sizes, not contents
aws s3control get-public-access-block --account-id ACCOUNT
aws accessanalyzer list-findings-v2 --analyzer-arn ARN --filter '{"resourceType":{"eq":["AWS::S3::Bucket"]}}'
```

For many buckets, use S3 Storage Lens / Access Analyzer / Macie / Security Hub findings rather than looping per bucket.

## 4. Troubleshooting 403 Access Denied

1. Identity: `aws sts get-caller-identity`.
2. Identity policy allows the action on the exact ARN (`bucket` for List, `bucket/*` for Get/Put).
3. Bucket policy: explicit denies (`aws:SourceVpce`, `aws:SecureTransport`, `aws:PrincipalOrgID`).
4. **KMS**: caller needs `kms:Decrypt` (read) / `kms:GenerateDataKey` (write) and the key policy must allow it; cross-account needs both sides.
5. Object Ownership / ACLs (legacy objects owned by another account).
6. SCPs / RCPs, VPC endpoint policy, access point policy.
7. Object does not exist and caller lacks `s3:ListBucket` → 403 instead of 404.
8. CloudTrail data events (if enabled) show the denied call.

## 5. Data operations (all are changes)

| Operation | Safety |
| --- | --- |
| Upload / sync to bucket | Show source, destination prefix and file count first; `--dryrun` |
| Delete objects | Versioned buckets keep noncurrent versions (recoverable until lifecycle expiry). `aws s3 rm --recursive` asks via the guard; always `--dryrun` first and confirm the exact prefix |
| Restore deleted object | Remove the delete marker (`delete-object --version-id <marker>`) or copy the previous version |
| Replication | CRR/SRR needs versioning on both sides, a replication role, and KMS permissions; existing objects need Batch Replication |
| Object Lock | Governance mode first; **compliance mode cannot be shortened or removed by anyone**, including root: humans decide |
| Lifecycle change | Expiration rules delete data permanently once applied: review carefully |

## 6. Detection

Macie automated sensitive data discovery; GuardDuty S3 Protection; Security Hub controls S3.1-S3.x; Access Analyzer for external access; Config rules `s3-bucket-public-read-prohibited`, `s3-bucket-ssl-requests-only`.

## Never

- Disable Block Public Access, add public ACLs, `Principal: *` allow policies, or `--acl public-read` uploads (guard-blocked).
- Delete buckets, suspend versioning, remove encryption/replication/lifecycle protections from an agent (guard-blocked).
- Download or print customer data to "check" a bucket; inspect metadata and counts instead.
- Generate long-lived presigned URLs or presign with an admin identity.
